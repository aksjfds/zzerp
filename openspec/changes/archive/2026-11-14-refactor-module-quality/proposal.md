## Why

上一轮建立了工具和规范，但未完成代码整改。本轮以职责单一、显式契约、业务规则单一来源、事务/资源生命周期明确和审查证据完整为标准，逐模块审查并修改真实问题，不能根据现有实现放宽标准。

## What Changes

- 收紧开发规范，启用 Ruff 默认复杂度上限 10，不新增忽略或提高上限。
- 工程公开路线契约采用明确值类型，隔离内部就绪查询，删除无调用的 ORM 暴露接口与预留事件抽象。
- planning 分离流水写命令、查询、序列化和统计，拆分高复杂度登记流程，保留锁、幂等、数量和隔离规则。
- 拆分图算法和架构检查的职责，补全入口/相对导入检查，避免漏检被误报为通过。
- 修正工程局部保存覆盖未保存内容、响应可编辑能力默认值、会话读取隐藏删除及前端显示偏好异常/异步生命周期问题。
- 前端生产计划 API 与业务类型分离；核对其余模块，只有实际问题才修改。

## Capabilities

### Modified Capabilities
- `development-workflow`: 明确独立质量标准与逐模块证据要求。
- `mes`: 明确工程局部保存不丢失其他未保存内容。

## Impact

覆盖后端五模块、domain/application/HTTP边界，前端工程/计划/客户/部门及共享代码，项目检查器。保持既定生产业务、HTTP字段、数据库结构和部署行为；不新增依赖、测试或功能，不执行构建、服务、实际数据库或 Git 写操作。密码存储策略、部署运维和新业务功能不在本轮结构/行为保持整改范围。
