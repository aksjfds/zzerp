## Goals / Non-Goals
目标为SQL可维护、约束无NULL漏洞、索引与真实查询匹配、减少全局读入和重复计算。所有改动依据本轮真实调用链；模块仍只操作自己的表。无性能实测条件，不承诺延迟或倍数改善。
非目标：改变生产规则、对既有库在线迁移、引入缓存/汇总快照/游标分页、部署或连接数据库、自动化测试。

## Decisions / Order
1. SQL：列后集中约束，外键全部命名且与ORM一致；流程图JSON结构约束使用IS TRUE确保缺失或JSON null不被CHECK当作通过。只检验对象/schema/数组形态，不在SQL解析节点或图。
2. 清理BOM未使用的两项GIN和未被引用的(id,product_id,version)唯一键、工单冗余product索引及无查询使用的计划status索引。保留必要组合外键及唯一键。增加订单号trigram索引；流水采用固定UTC秒截断表达式并配置工单/全局/配件到料索引；ticket聚合索引覆盖quantity并过滤NULL票。
3. 触发器固定search_path，票到料一次锁票并读取出料/物料/目标后验证，减少重复JOIN；原出料对比备注、同票累计上限、只追加和工单保护不变。schema不向PUBLIC授予创建权限，应用仍以建立基线账号拥有对象。
4. 工程api暴露只读标量Select窄查询（部门路线三列、产品或客户ID），不暴露ORM实例/类；planning组合为IN子查询，避免Python物化全局结果。分页后的显示仍用值类型接口。进度按计划EXISTS分页，避免工单展开后DISTINCT；票未收到使用相关NOT EXISTS；候选目标只查询直接后继。
5. 工程产品列表先分页，再计算本页BOM数量，版本列表直接读取版本号。保留编辑聚合加载与锁顺序。新增/products/options轻量限量候选接口，仅返回计划选品所需四字段、不计算BOM/图/total；前端使用该接口并延迟远程搜索，初始与客户切换立即查询。
6. planning新增内部流水聚合值，同一工单页的父行累计和子行直接到料复用一次分组查询；出料停留量也使用同一读取实现，计算规则不变，命令内仍先计划锁后产品锁。
7. 数据库一致性检查从架构脚本拆分，保留同一入口；共用少量AST读取辅助。增加CHECK表达式、外键目标/行为及函数定界检查，同步规范和README。先检查再逐项审查SQL—ORM—HTTP—前端；全部满足后归档。

## Risks / Review
表达式索引须固定UTC且查询表达式一致；秒内继续按ID升序，不能替换为微秒时间或舍入时间。分页与子查询必须在数据库内保留认证部门和产品隔离，不借性能优化取消规则。去重、FK删除行为、延迟唯一约束、只追加触发器逐项保留。新候选接口仅为响应裁剪，不能过滤掉现有可选产品。静态检查不能证明PostgreSQL执行计划、并发或实际耗时。

## Sources
PostgreSQL 17官方资料：CHECK在表达式为NULL时通过（https://www.postgresql.org/docs/17/ddl-constraints.html），表达式索引有写入成本（https://www.postgresql.org/docs/17/indexes-expressional.html），pg_trgm支持ILIKE（https://www.postgresql.org/docs/17/pgtrgm.html）。据此修复声明式缺口并为真实查询选择索引，避免无依据加索引。

### SQL变更与索引依据

- 所有25项外键均有显式名称；按本轮开始前SQL提取源列/目标/删除/延迟行为比对，25项关系行为全部相同。保留客户组合FK、当前版本延迟FK、计划工单身份和所有数量/状态约束。
- 正式/草稿图各用一个NULL安全结构CHECK，拒绝缺字段、JSON null和字符串schema版本；节点、BOM和路线业务仍由后端校验。
- 删除uq_product_bom_id_version（无任何引用），保留被路线组成引用的uq_product_bom_product。删除BOM名称/编号两项GIN（实际无模糊检索），删除工单product索引（route索引已有此前缀）、计划status索引（实际列表按更新时间，命令按主键锁）。
- 新增订单号GIN，对应工单/票/进度的ILIKE；产品客户索引扩展为customer_id/updated_at DESC/id DESC，对应选品和客户筛选列表。
- 替换原始时间流水索引，按固定UTC的秒截断表达式及ID排序：工单页索引覆盖direction/input_material_node_id/quantity以支持汇总；全局时间索引用于部门流水排序；配件到料索引带物料条件和receipt部分条件，用于子行先过滤再分页。票索引排除NULL并覆盖quantity，对应累计到料聚合与NOT EXISTS。
- SQL和ORM共24项显式索引，顺序、表达式、覆盖列与条件逐项静态一致。索引都有写入和空间成本，尚无实际执行计划或索引收益数据。
- 6个SQL函数固定search_path并统一定界。按函数体文本比对，仅validate_ticket_receipt改变：一次读取并锁票，同时得到数量/目标/来源物料，再做备注和累计校验；其余5个函数体保持。6个历史UPDATE/DELETE/TRUNCATE拦截触发器、工单保护及更新时间触发器保留。开发种子段与本轮前完全一致。

### 前后端查询证据

| 调用路径 | 原问题 | 当前实现 |
| --- | --- | --- |
| 部门工单、部门流水、交接票 | 全局路线及BOM组成读入Python，再拼大量IN参数 | 工程api提供三列标量Select，planning在数据库内用子查询限定认证部门，分页后才取本页展示引用 |
| 产品/客户名称筛选 | 先取全部匹配ID集合，列表和count还会重复读取 | 两所属模块公开ID Select，查询组合使用子查询，未暴露ORM或增加反向依赖 |
| 生产进度分页 | 工单JOIN放大计划后DISTINCT | 计划EXISTS筛选后分页，页内保持各订单筛选范围内全部工单，原图排序和订单隔离不变 |
| 票与出料候选 | 未到料先构造全集，候选加载同产品所有安排 | 相关NOT EXISTS；仅查询同计划同产品直接后继，再核对目标是否已安排 |
| 工单累计、装配子行、停留量 | 父行和子行重复SUM，停留量另有一套读法 | 内部MovementTotals及一次分组读取；子行只取原始配件直接到料，父行保留整套/嵌套分项，精确齐套公式未改 |
| 工程列表和版本号 | 全部产品先关联聚合BOM；版本号加载全聚合及图 | 产品子查询先分页，本页相关计数；版本号仅读取版本表并保持倒序/404 |
| 计划选品 | 完整产品列表、BOM计数、图校验和total都被丢弃 | /products/options只返回id/customer_id/product_name/factory_code，最多50条；复用相同客户与关键词条件和排序，不过滤现有可选产品 |
| 选品输入 | 每次远程调用走重型列表 | 新接口加250ms页面延迟，输入立即取消旧请求，初始及客户变更立即加载，卸载清理定时器；关闭Select自带延迟以避免叠加 |

权限与稳定性审查：生产请求仍由会话部门强制隔离，轻量选品仍要求PRODUCT_VIEW；同计划/同产品/直接路线和子行过滤口径保持。写命令的计划→产品→票锁、UUID重放先于状态/容量校验、超停留备注和分批票备注均未移除。源SQL与后端均保留票累计上限，零/负停留量仍可有备注出料。未增加缓存、数量快照、数据库图解析、旧接口兼容或自动化测试。
