## Confirmed Decisions
1. 产品共用一份BOM，新增/修改配件在产品层完成，不复制到外观。
2. 外观是并行业务实体，不是递增版本：名称如金色、银色，同产品内唯一，使用独立稳定ID。每个外观分别拥有正式图及草稿。
3. 同计划允许同产品多个外观，按产品＋外观分条填写订单数量、生产数量。不得用一个所谓当前外观替所有计划切换路线。
4. 版本号概念删除；expected_revision仍用于乐观并发校验，schema_version仍描述图JSON格式，均不可盲目替换。

## Target Model
- product：客户、名称、厂编、客编、revision及基础时间；无当前版本/当前外观指针。
- product_bom：产品共用BOM，唯一产品/配件编号与产品/排序号；删除product_version外键和字段，保留被节点/工单引用的配件身份保护。
- product_appearance：稳定ID、product_id、appearance_name及创建时间；产品内名称唯一，组合唯一键用于关系保护。
- product_process_flow：产品/外观各一份正式图与可选草稿；节点引用所属产品BOM。
- 当前route/component投影：身份增加appearance_id；正式图只更新所属外观，不影响其它外观。
- production_plan_item：主键计划/产品/外观，客户及外观组合外键保护；两项数量按此明细保存。
- department_work_order：计划/产品/外观/物料节点/部门节点唯一；通过组合FK引用明细及外观投影。仍实时解析当前资料，不增加版本/物料/路线快照。

## Order
1. 先改SQL与所属ORM/契约，移除产品版本实体，保留并发修订号/图schema；更新示例数据为真实外观。
2. 工程改为产品BOM＋按外观读写图/投影，增加外观创建、改名及从现有外观复制流程；复制保留节点ID，共用BOM无需重映射。
3. 工程引用保护按外观查询已有工单/交接；共用BOM删除和编号修改检查所有外观正式图、草稿和历史引用，不允许通过修改共用数据间接破坏其它外观。
4. planning全部路由键/查询上下文/明细/工单/统计加入外观身份；同产品不同外观禁止交接，数据库票校验同步。父计划锁→产品ID排序锁保持，事务内重建全部明细与工单。
5. 前端替换版本选择和按钮为命名外观管理；BOM区域标明产品共用；计划选品按产品＋外观标识，列表、票、流水、进度展示外观，行key包含外观身份。
6. 完成静态约束/依赖/类型/边界/OpenSpec检查，逐项审查业务不变量后同步正式规范并归档。

## Risks and Completion
共享BOM修改必须覆盖所有外观保护；同产品各外观可重复节点ID，所有字典键和SQL JOIN须含外观；进度不能合并外观；禁止跨外观交接；历史流水始终只追加。正式图/草稿、直接关系保护、齐套算法及原始配件统计口径保持。只做源码及静态验证，不宣称数据库并发或页面运行验收通过。

## Current Status
实施与源码审查已完成。正式SQL、ORM、工程/计划模块、HTTP契约和前端已同步；数据模型草案已删除，zzerp.sql仍为唯一开发重建基线。旧产品版本表、字段、指针、代码与接口已移除，没有旧结构兼容分支。
