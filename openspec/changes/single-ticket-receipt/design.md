# 设计

现有登记先持有计划锁、产品锁，并按请求ID查重，再锁交接票。继续保留此顺序：相同请求重试返回原结果；新请求在票行锁后查询是否已有到料，存在则409拒绝，无论剩余数量多少。不改变所属部门、正式路线、计划确认及物料限制。

数据库基线将 ticket_id 的普通索引替换为可空唯一约束，允许多条无票外部到料；票面数量、少到备注仍由原触发器校验，改为拒绝已有票据到料，不再累计接收。现存历史不删除、不回填；本轮不执行真实数据库DDL。已有历史分批记录在后端视为已登记，不再追加；如后续对现存库加唯一约束，必须先独立处理历史重复，不能直接覆盖不可变流水。

前端按已登记数量是否大于0判断结票，展示未登记/已登记状态，隐藏已登记票的操作按钮，删除“剩余可到料”和分批接收文案。允许单次少到料但必须备注，票后续不可补录。无新接口或依赖，不增测试；以无缓存静态检查核对。
