# 外购入库工艺

外购配件继续使用 BOM 配件节点，并把仓库部门的“外购入库”配置为该配件的首道工艺。

推荐流程：

```text
外购配件 -> 外购入库 -> 装配或后续工艺
```

“外购入库”是 `flow_json` 中的宏观工艺，在数据库中使用 `procedure_type = purchase_receipt` 标识。
业务判断不得依赖可修改的工序名称。开工单时输入实际 `substep` 名称，服务会复用或新建该
工艺下的 `procedure_substep`；种子数据中的“全工序”只是输入建议，不是预配路线。工单的
`work_order_type` 为 `substep`，`work_order_name` 保存“外购入库-具体步骤”的显示快照；
分批到货规则仍由所属宏观工艺的 `procedure_type` 判断。

订单确认后，外购配件需求进入仓库部门。仓库创建外购入库工单，并可按实际到货数量分批登记。
每次登记完工数量时选择直接完成或送 QC：直接完成立即进入装配或后续宏观工艺；送 QC 则先生成待检
批次，合格数量进入相同目标，返工数量回到本次工单的来源位置。外购入库保持单步到货语义，
客户端不发送 `continuation_action` 或下一 substep；目标由 `purchase_receipt` 类型固定决定，不会自动续开
下一个 substep 工单。QC 不再作为 `flow_json` 节点，也不配置合格品去向。
全部数量到货并提交后外购入库工单关闭。

当前版本只管理需求数量和到货流转，不包含供应商、价格、采购审批、付款和退货。需要这些能力时应新增独立采购单领域，外购入库工艺继续作为采购到货与生产流程之间的边界。
