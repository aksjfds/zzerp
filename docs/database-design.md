# 生产标记数据设计

## 客户、产品与订单

`customer` 保存工程部和业务部共用的客户主数据，客户名称唯一。`product.customer_id` 和 `customer_order.customer_id` 都引用客户表，接口仅为展示返回 `customer_name`，不再把客户名称重复保存到产品或订单中。

工程部创建产品时可以选择已有客户，也可以输入新客户名称；新客户与产品在同一事务内创建。业务部创建订单时必须先选择客户，产品候选项只显示该客户名下的产品，后端同时校验每条订单产品的所属客户，避免绕过前端提交混合客户订单。

PMC 账号使用只读订单与生产权限，进入独立 PMC 看板。订单产品进度以订单产品单位统计：完工取最终 QC 的累计合格数量（已发货数量作为兼容兜底）；报废、遗失按物料用量折算并以瓶颈物料路线为准；未完工等于总数扣除完工、报废和遗失。欠 PO 是未完工中的子集，表示外购节点当前库存尚未被开放外购入库工单覆盖的数量。

标准工艺不再配置子步骤或固定顺序。`procedure_tag` 保存工艺下可复用的标记名称。`procedure_tag_set` 与 `procedure_tag_set_member` 保存无序标记集合，排序后的标记 ID 组成 `tag_key`，因此 `粗1 + 粗2` 与 `粗2 + 粗1` 是同一个组合。

`procedure_tag_price` 按 `product_id + product_version + origin_flow_node_id + procedure_tag` 配置某个实体配件在该工艺下必须完成的全部标记及计件单价。来源节点既可以是 BOM 配件节点，也可以是装配输出节点，因此装配后的标准工艺使用同一套配置和开单规则。单价可以暂时为空，但不能小于 0；配置项不保存标记顺序。该配件来源与工艺开出第一张工单后，标记集合冻结，只允许修改单价。

未打标记数量仍在 `repository`。完成至少一个标记的数量进入 `procedure_tag_stock`，按生产项、流程节点、来源节点、部门和标记组合合并。组合不为空时才允许从标准工艺出货。

标准工单使用 `work_order_type = tag`，并记录：

- `procedure_id`：所属宏观工艺；
- `applied_tag_set_id`：本张工单一次新增的标记集合，至少包含一个标记；
- `source_tag_set_id`：开单来源组合，未打标记时为空；
- `target_tag_set_id`：来源组合与本次新增集合合并后的目标组合；
- `repository_id` 或 `procedure_tag_stock_id`：创建时必须且只能保留一个库存来源。

外购入库继续使用 `purchase_receipt` 工单，装配继续使用 `assembly` 工单，两者不使用标记集合。

本次新增集合不能为空，也不能与来源集合重叠，目标集合必须严格等于两者的并集。一张工单可以一次增加多个标记，但仍只产生一张工单。

所有标准工艺完成标记后必须送检，因此标准工艺节点必须直接连接独立 QC 节点，生产部门不能直接完成标记或直接出货。非最终标记的合格数量回到原工艺形成目标标记组合，继续开下一张标记工单；最终标记的合格数量停留在 QC，只有 QC 可以放行到流程图配置的后续节点。

每张标记工单只要全部开单数量已经送检、没有待检数量且没有待返工数量，系统就自动结单。QC 合格数量无需等待结单即可继续下一标记或由 QC 放行；返工数量回到原工单继续加工，报废和遗失离开生产数量。`production_movement` 同时保存流程节点、部门和来源/目标标记集合快照。

流程图以 `shipping`（发货）节点作为终点。发货节点必须且只能接在 QC 后面；到达发货节点只记录出货流动，不再生成生产库存。普通工艺或装配跨部门流转时必须先经过 QC。装配节点若连接 QC，同样生成送检批次，返工回原装配工单，合格品由 QC 放行。

`work_order_batch.rework_source_batch_id` 表示返工复检批次的来源 QC 批次。首次送检为空；返工再次送检时创建同一工单的新批次并指向来源批次。一个批次的待返工数量等于其返工数量减去全部子批次送检数量。

标记组合横栏按当前库存、开放工单、待检批次和非取消工单历史派生，展示组合名称、加工中、质检中和已完成。工单历史保留实际开单顺序，但标记组合本身没有顺序。

开工单时，选择框只允许选择该实体配件来源在 `procedure_tag_price` 中已配置且尚未完成的标记。目标组合等于全部配置标记时，该工单为最终标记工单。未配置必做标记时不能开单。

`production_operation_undo` 保存生产部门每次送检、返工送检、直接完成和装配提交前后的工单、库存、批次与流动快照。工单卡片只提供最后一次操作的撤回入口；QC 已录入、库存已变化、产出已进入后续工单或存在更晚操作时拒绝撤回。成功撤回会在同一事务中删除本次批次和流动、恢复原库存与工单进度，并保留操作人、撤回人和撤回时间作为审计记录。

各生产部门可以维护本部门 `worker`。存在车间的部门录入工人时必须选择本部门车间；没有车间的部门录入为部门直属。数据库分别限制同一车间的同名工人和同一部门直属的同名工人，管理端工人总览保持只读。
